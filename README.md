# 每日四象限

### 打开地址

```
https://daily-quadrant-32717.app.workbuddy.host/?sharecode=SI4C4EK6BF
```

把上面这一行完整复制进浏览器地址栏就行，不用点任何链接。域名是本项目的托管子域；末尾的 `sharecode` 是站点对外开放用的分享码，不是追踪参数。

不用装、不用注册也能先试：打开后点「游客用一下」，任务存在你本机，换设备不同步。

一个我自己每天在用的任务工具。说一句话记任务，它自己认日期、问三个问题判轻重；首页只推当天最重要的三件；临近截止主动推给你。

**可以几个人一起用**：各自注册账号，任务互相看不到。提醒发到各自绑定的邮箱。

技术栈刻意选得无聊：**Python 标准库 + SQLite，零第三方 Python 依赖**。这不是偷懒，是决定——一个要长期跑在便宜机器上的个人工具，依赖越少越不会在某天因为某个包升级而挂掉。

## 我为什么这么做

我真实的问题是「记不住任务」，不是「缺一个分类工具」。四象限只是我最先想到的解，不是问题本身。所以这个产品的主线是三个动作：

1. **降低记录成本**：不让用户填五个字段。说人话，系统翻译成结构。
2. **替用户做选择**：四宫格是给人看的，不是给人挑的。真正要做的是从一堆事里挑出今天三件。
3. **在用户不看的时候也提醒**：记了不看等于没记。

细节我记在 [`CHANGELOG.md`](CHANGELOG.md)，每一版都写了「改了什么 / 为什么改 / 放弃了什么」。想理解我的判断过程，先看那个文件。

## 它怎么跑起来的

```
浏览器 ──HTTP──> Python HTTP 服务 ──SQL──> SQLite (data.db)
                      │
                      ├─ 每分钟扫描到点任务 ───> 微信 / 浏览器推送
                      └─ openssl 签 ES256 ──────> Web Push 网关
```

没有框架。`server.py` 里一个 `Handler` 类处理所有路由，`sqlite3` 直接写 SQL。前端三个原生 JS 文件，没有构建步骤。

**为什么不用 Flask/FastAPI**：这个项目的复杂度不值得引框架。标准库够用，部署时少一堆 `pip install`，也少一堆版本冲突。代价是路由代码有点糙，我接受。

**为什么 SQLite 存整份状态 JSON**：任务结构会变（`statusDate`、`carryCount`、`history` 都是后加的）。整份存 JSON，加字段不用改表结构。代价是不能按字段查——但数据量是个人级，全读出来在内存里过滤反而更快。

### 关键实现，以及怎么验

| 功能 | 实现方式 | 自己验的方法 |
|---|---|---|
| 中文日期解析 | `capture.js` 正则 + 自然周基准，含今晚/明晚等时段词 | `node -e "global.window=global; require('./capture.js'); console.log(window.Capture.parse('今晚交报表'))"` |
| 判断粒度 | 三问（重要 1–5、紧急 1–5、费劲 1–5）→ 3×3 共 9 格，编号越大越优先 | 新增任务，第三步三问都选最低档，应显示「可以不做」 |
| 先这三件 | 按逾期程度、截止远近、象限权重、是否今天有钟点打分排序；难度≤2 且重要度≤6 的进「顺手清掉」，不占三件名额 | 造几个不同截止日的任务，看焦点区顺序 |
| 提醒错峰 | 提前量 = 难度打底 + 重要度加权（上限 60 分），相邻两条至少隔 10 分钟，撞车自动后推 | 建两条同时间的任务，看徽章上的提醒时刻是否错开 |
| 跨天增补 | 前端比对 `lastOpenDate`，未完成的顺延并累计 `carryCount`，逾期自动升级 | 改系统日期到明天，刷新页面 |
| 密码安全 | PBKDF2-HMAC-SHA256，20 万轮，16 字节随机盐 | 直接打开 `data.db` 看 `pass_hash`，是哈希不是明文 |
| 会话 | 随机 token 存服务端，HttpOnly + SameSite=Lax Cookie | 浏览器 DevTools 看 Cookie，勾着 HttpOnly |
| 账号隔离 | 所有查询带 `user_id` | 注册两个账号，各建一条任务，互相登录看 |
| Web Push | openssl 生成 P-256 密钥，手写 ES256 JWT，发空 payload，前端收到再拉消息 | 页面点「测试推送」 |
| 主动提醒 | 浏览器推送 + 微信（PushPlus）；邮件不参与日常提醒 | 手机点「开启主动提醒」，等到点看是否弹通知 |
| 提醒强度 | settings.reminder_mode，安静只入站内列表，强制用 `Urgency: high` | 切成安静后点「测试推送」，应只在列表里看到 |
| 找回密码 | 6 位码存 SHA-256，10 分钟过期，一次性 | 点「找回密码」收码，用完再试应被拒 |
| 注册防护 | 邮箱全局唯一；同一来源每小时最多 8 次注册 | 同一邮箱注册两次，应报「已绑过账号」 |

**为什么 Web Push 发空 payload**：本来想用 `pywebpush`，它依赖 `http-ece`，当前环境没有可用的 wheel，装不上。改成自己签 VAPID、发空消息触发前端拉取。依赖从 3 个降到 0 个。

**为什么不做邮件提醒**：做过，又下线了。邮件打开率低，提醒晚几分钟等于没提醒；而且免费邮箱每天有发信额度，人一多就会顶到上限，最要命的是它会把「注册」卡住——验证码发不出去，新用户就进不来。现在提醒只走浏览器推送和微信，邮件只在「找回密码」时发一次。这个取舍是产品负责人拍的板。

**为什么注册不收验证码**：验证码依赖 SMTP，配错一个端口或授权码过期，所有人都注册不了。小范围使用（几十人）宁可少一道验证，也不能让人卡在门口。邮箱仍然必填，用途是找回密码。

## 跑起来

```bash
python3 server.py
```

默认 `3000` 端口，`PORT` 环境变量可改。绑 `0.0.0.0`。

数据默认放在 `~/.daily-quadrant/`（`DQ_DATA_DIR` 可覆盖），首次启动自动建 `data.db` 和 `vapid_private.pem`。**数据不在代码目录里**——容器化部署会替换整个代码目录，放里面等于每次清库。

**数据不只活在容器里**：`daily-sync.py` 每天把线上全部用户与任务拉到本机，再推进私有仓库 `daily-quadrant-data`。容器整个没了，最多丢一天，而且能一键写回（`restore.py`）。凭据走环境变量 `DQ_USER` / `DQ_PASS`，不落盘。

**发布会不会清数据**：不会。发布做的是「复用原沙箱，用上传的代码目录覆盖线上代码目录」，不重建整台机器。只要数据不在上传目录内，改代码随便发。想确认就调 `GET /api/health`，发布前后对比 `users`、`tasks` 两个数字。

需要 Python 3 和 openssl（用来生成推送密钥）。不需要 `pip install`。

**发信服务**（只用于找回密码）由管理员在「站点设置」里配置，该面板只对管理员可见。填的是 SMTP 授权码，不是登录密码。不配也能正常注册、正常用——只是「找回密码」用不了，忘了密码只能找管理员。

支持 QQ、163、Gmail。**Outlook / Hotmail 个人邮箱不可用**：微软 2024-09-16 起关闭了 Basic Auth，`smtplib` 密码登录必然报 `535 5.7.139`，不支持 OAuth 就无解。

配好之后：「找回密码」可用。新用户注册**不需要**邮箱验证码。

**提醒强度**（每个用户自己选）：安静=只进站内列表，不弹任何通知；普通=静默通知不响铃；强制=响铃。即使任务被判成「不做要出事」，也能设成安静——避免紧急事项打断生活。实现上通过 Web Push 的 `Urgency` 头控制：`low` 静默、`high` 响铃；安静模式直接不发 Web Push 和微信。

## 安全边界，说实话

我做了什么：
- 密码加盐哈希，不存明文
- 会话 Cookie HttpOnly + SameSite=Lax
- 邮箱唯一，验证码一次性、10 分钟过期
- 接口全部带 `user_id` 过滤
- 管理员接口单独鉴权

我没做什么，以及为什么：
- **不提供 HTTPS**：需要由外层反向代理终止 TLS。裸跑在公网等于密码明文过网，别这么干。
- **没有速率限制的全覆盖**：只有发验证码限了 60 秒。登录接口没做暴力破解防护。个人工具够用，公开部署要补。
- **没有 CSRF token**：SameSite=Lax 挡掉了大部分场景，不是完整方案。
- **不做异地备份**：备份是使用者自己的责任。重要数据请定期用页面上的「导出」，或自行备份数据库文件。

## 明确没做的东西

- **AI**：日期解析和轻重判断用确定性规则。零调用成本、可预测、离线可用。这个产品的定位是「实用工具」，不是「AI 应用」。要接 LLM 随时可以替换 `capture.js`，但那不是当前的目标。
- **手机号验证**：国内短信要实名、套餐、签名报备，成本远超这个工具本身。邮箱够用。
- **原生桌面小组件**：Android AppWidgetProvider 和 iOS WidgetKit 是两套原生协议，Web 做不到。PWA「添加到主屏幕」只是个图标。
- **任务自动排序到细粒度**：四象限不能告诉用户「三个都重要不紧急时先做哪个」。当前的三件排序是我的启发式，不是标准答案。

## 部署

任何支持 Python 的主机都能跑。要求监听 `PORT`、绑 `0.0.0.0`。反向代理要正确转发 HTTPS，否则 Web Push 注册不了（「找回密码」不受影响）。

数据库是单文件 `data.db`，和 `vapid_private.pem` 一起放在数据目录（默认 `~/.daily-quadrant/`）。迁移时这两个一起带走：用户数据和不重复推送的密钥都在里面。

## 文件说明

| 文件 | 作用 |

| `server.py` | 后端全部逻辑：路由、数据库、推送、找回密码邮件、定时任务 |
| `app.js` | 前端逻辑：渲染、向导、回顾、登录、各设置面板 |

| `sw.js` | Service Worker，处理浏览器通知 |
| `manifest.webmanifest` / `icon.svg` | PWA 配置与图标 |
| `CHANGELOG.md` | 版本记录，含每次的取舍理由 |
| `sync-check.py` | 一键核对：工作区是否干净、远程是否真收到、线上跑的是哪一版 |
| `docs/` | 开发准则、产品原则、协作经验。规范跟代码放一起，不散落在本机各处 |
| `.gitignore` | 排除 `data.db`、`vapid_private.pem`、`.env`、`__pycache__` |

后两个是运行时生成的私密文件，**永远不要提交**。

### 改完代码的固定动作

```bash
python sync-check.py --push
```

它做三件事，缺一件就报出来：有没有没提交的改动、本地和远程的提交号一不一样、线上跑的是不是这一版。三项全对上才算改完。**只在本机改、没推上去，等于没写** —— 机器坏一次就全没了。
