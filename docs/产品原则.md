# 好产品的原则

> 这是给我自己看的。每次做东西之前读一遍，做完之后照着检查一遍。

## 我为什么写这个

我有真实的需求：我经常记不住任务。

我不是在为抽象的"用户"做东西，我是在为我自己做东西。我在乎三件事：教程好不好、界面清不清楚、用起来有没有被当成傻子。

这三条不是加分项。它们就是产品本身。

## 一句话说清我的判断

AI 让"做功能"变得很便宜。功能不再构成壁垒。

剩下的壁垒只有一个：你有没有真的替使用者想过。

功能可以被复制。体贴不能。

**最具体的体贴**：任务在前，人是有压力的。用轻松的话消解这份压力，用自嘲替代说教，用幽默替代警告。这才是产品真正立足的依靠——不是 engag 指标，是用户在最烦的时候打开你，嘴角松了一下。

契诃夫的路子：一屁股债还在写信调侃「天气好极了，钱几乎没有」「我认为休息一下是合法的」。不否认困难，但把狼狈说得轻巧。这正是任务工具该有的语气——你面对的是一堆没做完的事，不是险情报告。

**尺度**：只在说明和提醒处点缀。按钮、标题、错误信息保持直白。满屏名言会腻，也会干扰判断。

**清爽不等于藏起来。** 把功能塞进「更多」却不提示，等于让用户去猜——万一他不点呢？人性化的底线是：让人知道有什么，不是让人找不到。收起可以，但入口本身要说清里面装着什么。首次使用的引导要默认可见，老用户收起过再记住他的选择。

## 七条原则

### 1. 先解决一个真问题，不是先画一张大图

反例：我要做一个全能效率平台，有任务、有日历、有笔记、有统计。

正例：我记不住任务，那就做一个"不会忘"的东西。别的先不做。

自检：如果只能保留一个功能，留哪个？留的那个才是你的产品。

### 2. 消灭操作，不是美化操作

反例：把填表界面做得很好看，用户还是要填五个字段。

正例：用户说一句"下周三交方案"，系统自己填好五个字段。

自检：用户完成一次核心动作要几步？超过三步就重做。

### 3. 不要求用户先学习

反例：新用户进来先弹窗"欢迎，让我们介绍一下四象限法则"。

正例：新用户进来直接能打字。术语以后再说，最好永远不说。

自检：一个没看过任何说明的人，能不能在十秒内用起来？

### 4. 术语藏起来，结果露出来

反例：界面上写"设置您的优先级矩阵配置文件"。

正例：界面上写"今天先做这三件"。

自检：把界面上的专业名词遮住，用户还知道该干嘛吗？知道就对了。

### 5. 提醒要说人话

反例："任务 #12 已逾期 3 天，状态：未完成。"

正例："你前天说要交方案，还剩一天。要我帮你拆成两步吗？"

自检：这条通知如果是你朋友发的，你会觉得他在教训你吗？会就重写。

### 6. 默认路径只有一条

反例：设置页二十个开关，用户不知道该开哪个。

正例：打开就能用，高级设置藏在"更多"里。

自检：用户第一次用，会不会卡在"我该点哪"？会就说明选项太多。

### 7. 能退出、能反悔、能带走

反例：删了就没了，数据锁死在你的平台。

正例：误删能撤销，数据能导出，账号能注销。

自检：用户想离开的时候会不会觉得被卡住？会就是设计有问题。

## 知识霸凌清单

知识霸凌 = 用术语、流程、专业概念，让用户觉得自己笨。

这是最伤人的产品设计。它把"产品的问题"变成"用户的无能"。

**别做这些**

- 一上来就教概念，还没让用户尝到甜头
- "你需要先了解 XX 才能使用"
- 报错直接贴系统话：Error 500、null pointer
- 帮助文档比产品本身还长
- 按钮上写黑话："提交配置以生效"
- 用缩写不解释：Q2、OKR、SLA

**改成这样**

- 先让他用起来，用顺了再解释
- 报错说人话："没保存成功，网络好像断了，再试一次？"
- 术语第一次出现时顺手用一句话解释
- 按钮写清楚后果："删除这个任务"，而不是"确认操作"

一句话判断：用户用完是觉得自己变强了，还是觉得自己很笨？

## 发布前清单

- [ ] 一个没看过说明的人，十秒内能用起来吗？
- [ ] 核心动作能在三步内完成吗？
- [ ] 界面上有专业术语吗？能删就删
- [ ] 所有提示和报错都说人话吗？
- [ ] 教程有没有图示？不是纯文字
- [ ] 误操作能撤销吗？
- [ ] 数据能导出吗？
- [ ] 手机上好用吗？
- [ ] 有没有"做完了"的反馈，而不是冷冰冰的"操作成功"？
- [ ] 我自己愿意天天用吗？

最后一条最重要。自己都不用，别给别人用。

## 用到四象限这个产品上

差异化不靠"更漂亮"或"更便宜"。那两条路已经挤满了人。靠这三条：

**1. 一句话捕获。** 用户不需要懂四象限。他说一句"下周三前把方案交了"，系统自己判断象限、自己设日期。手动填表是上一代产品的做法。

**2. 每天只给三条。** 不要给用户一张四宫格让他自己挑。表是给人看的，三条是给人做的。选择本身就是负担。

**3. 提醒像人说的。** "你前天说的方案，明天到期了。要不要我帮你拆成两步？"——这才是温度。

再加一条反直觉的：**把"四象限"这个词藏起来。** 它是我组织信息的内部方法，不是用户要学的知识。用户只需要看到"今天做这三件"。

## 最终判断标准

没有我在旁边推销，他第二天还会回来用吗？

会，就是好产品。

不会，做得再漂亮也是自嗨。
